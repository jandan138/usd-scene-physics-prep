# 文档系统规范化实施计划

基于用户需求，我制定了以下文档规范化实施计划。该计划将从清理、规范化、索引管理、代码关联、版本控制和自动化六个维度对现有的 `docs/` 目录进行重构。

## 1. 文档清理与审核 (Audit & Cleanup)
**目标**: 移除冗余文档，确保所有文档与当前代码库（尤其是 `simready` 体系）保持一致。

*   **保留**: 核心架构文档 (`architecture/`), 模块说明 (`modules/`), 使用指南 (`usage/`), 规范说明 (`specs/`, `specs_normalizer/`)。
*   **合并/重构**:
    *   `docs/overview/docs_index.md` 和 `docs/catalog.md` 和 `docs/index.md` 功能高度重叠。**计划合并为单一入口 `docs/INDEX.md`**，作为全局索引。
    *   `docs/changes/` 下的变更日志应统一管理，不再散落在单独文件中，或整合进 `CHANGELOG.md`。
*   **删除标准**:
    *   与当前代码库完全脱节的旧版操作文档。
    *   重复的索引文件（如 `docs_index.md`）。

## 2. 文档规范化标准 (Standardization)
**目标**: 统一 Markdown 格式和元数据头。

*   **元数据头模板**:
    ```markdown
    ---
    title: [文档标题]
    code_reference: [关联代码路径]
    created_at: YYYY-MM-DD
    updated_at: YYYY-MM-DD
    maintainer: [维护者]
    status: [Active/Deprecated/Draft]
    ---
    ```
    *注：使用 YAML Front Matter 格式，利于后续工具解析。*

*   **内容规范**:
    *   使用标准 Markdown (CommonMark)。
    *   代码块必须指定语言（如 ```python）。
    *   文件路径使用相对路径或项目根路径引用。

## 3. 代码关联管理 (Code Linkage)
**目标**: 实现文档与代码的双向可追溯。

*   **实施动作**:
    *   遍历所有 `.md` 文件，在头部 `code_reference` 字段中填入精确的代码路径（如 `set_physics/simready.py`）。
    *   在正文中引用代码时，使用 Markdown 链接格式：`[func_name](file_path#L10-L20)`。

## 4. 索引管理系统 (Indexing)
**目标**: 建立层级化、状态可视化的全局索引。

*   **创建 `docs/INDEX.md`**:
    *   **结构**:
        1.  **Project Overview** (项目概览)
        2.  **Architecture** (架构设计)
        3.  **Modules** (模块详解 - 自动提取元数据中的 `code_reference`)
        4.  **Usage** (使用指南)
        5.  **Operations** (运维与排错)
        6.  **Specs** (规范标准)
    *   **自动化生成**: 编写一个脚本 `scripts/generate_docs_index.py`，扫描 `docs/` 下所有 `.md` 文件的元数据，自动生成/更新 `INDEX.md`。

## 5. 版本控制与自动化 (Versioning & Automation)
**目标**: 确保文档质量和时效性。

*   **变更日志**: 创建 `docs/CHANGELOG.md`，记录文档系统的重大变更。
*   **自动化脚本**:
    *   `scripts/validate_docs.py`: 检查是否所有文档都有元数据头，检查 `code_reference` 指向的文件是否存在。

## 执行步骤 (Execution Steps)

1.  **清理冗余**: 删除 `docs/overview/docs_index.md` 和 `docs/catalog.md`，保留 `docs/index.md` 作为主页（或重命名为 `README.md`），新建 `docs/INDEX.md` 作为详细索引。
2.  **标准化格式**: 逐个更新 `docs/` 下的核心文档，添加 YAML 元数据头，修正格式。
3.  **代码关联**: 在文档中补充缺失的代码引用链接。
4.  **生成索引**: 编写并运行索引生成脚本，产出 `docs/INDEX.md`。
5.  **验证**: 运行验证脚本，确保无死链和格式错误。
