# 标准化更新流程设计

为了确保代码更新后文档的同步性，以及文档系统的一致性，我制定了以下标准化更新流程。

## 1. 核心流程设计

我们将建立一个**"双向同步，自动化辅助"**的维护流程。

### 场景 A：代码发生变更 (Code Update)
当开发者修改了代码（如 `set_physics/simready.py`）时：
1.  **查询关联文档**: 使用 `doc_manager.py` 工具反向查询引用了该代码的所有文档。
2.  **更新文档内容**: 针对受影响的文档，更新技术细节、参数说明等。
3.  **更新元数据**: 修改文档头部的 `updated_at` 字段。
4.  **提交检查**: 提交前运行校验脚本，确保未破坏文档结构。

### 场景 B：文档发生变更 (Doc Update)
当开发者修改或新增了文档时：
1.  **完善元数据**: 确保 YAML 头部包含正确的 `code_reference`（如适用）和 `updated_at`。
2.  **重置索引**: 运行 `doc_manager.py --gen-index` 自动更新全局目录 `INDEX.md`，确保最新状态被反映。

## 2. 工具增强计划

为了支撑上述流程，我将升级 `scripts/doc_manager.py`：
*   **新增功能 `--find-refs <file_path>`**: 输入代码路径，自动列出所有在 `code_reference` 中引用了该代码的 Markdown 文件。
    *   *价值*: 解决"改了代码不知道该改哪个文档"的痛点。

## 3. 落地实施步骤

1.  **工具升级**: 修改 `scripts/doc_manager.py`，实现反向查找功能。
2.  **流程文档化**: 创建 `docs/MAINTENANCE_WORKFLOW.md`，将上述标准流程固化为文档，供团队查阅。
3.  **验证**: 模拟一次代码更新流程，演示如何使用工具定位并更新文档。
